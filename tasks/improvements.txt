1. MASKED FINANCIAL DATA STILL SITS IN LANGFUSE PROMPT TEXT          [OPEN, decision needed]
================================================================================
WHAT
  masterStep embeds the masked bureau profile as a JSON STRING inside the master prompt
  (workflows/credix-workflow.ts, the `User profile (masked):` line). Key-based omission cannot
  reach inside a string, so loan structure and amounts reach Langfuse on every turn.

MEASURED (2026-08-03, real bureau backed turn, trace read back through the API)
  - Structured payloads: GONE. bureau_profile / masked_profile / signals are dropped recursively from
    span input and output (commit 1c806be). 18 `[omitted]` markers in the span tree.
  - Identity: emails 0, AGE_EXACT / income keys 0, mobile only as the deliberate trace user id.
  - Residual: ~376 financial key-name hits, all of them inside prompt text and memory processor spans.

WHY IT IS A DECISION, NOT A BUG
  The prompt is the one payload LLM tracing exists to show. Removing it means either redacting inside
  prompt strings (guts the trace, you lose the ability to debug what the model saw) or not giving the
  model the profile (impossible, it is the product). Options, in ascending cost:
    a) accept it, and rely on the destination being compliance tier
    b) redact only numeric amounts in prompt strings, keep structure legible
    c) hideInput on the generation spans only, keep step spans readable
  Cost of (a) is zero and it is the current state. Pick deliberately rather than by drift.

4. RAW MOBILE AS THE LANGFUSE USER ID                                [DEFERRED by product, 2026-08-03]
================================================================================
WHAT
  server.ts passes the raw 10 digit mobile as tracingOptions.metadata.userId, and
  identifierScrubProcessor exempts that one field from the value scrub so it survives export.

STATUS
  Deliberate product decision. HMAC hashing and omitting the field were both offered and declined.
  The two PR #19 threads were CLOSED on 2026-08-03 as accepted-decision, not as fixed, each with a
  comment that says so in the first line so a resolved thread cannot be misread as "the PII left":
    - src/mastra/server.ts:192
    - src/mastra/lib/langfuse-observability.ts:58
  The code is unchanged. This ledger item is now the only tracker; the PR will not remind anyone.
  A second reviewer (Copilot, third pass) flagged it again citing AGENTS.md:15, and suppressed the
  comment as a duplicate. So there are now two independent bots against one product decision.

WHAT BOUNDS IT TODAY
  - buildObservability() refuses to export unless LANGFUSE_BASE_URL is set, so the SDK can never fall
    back to the public cloud host. Current destination is the HIPAA tier instance.
  - Verified: the mobile appears ONLY as the user.id attribute (trace level plus its per observation
    copy). Zero occurrences in prompts, messages, tool I/O or payloads.
  - The prompt no longer carries it either, as of fc8b370.

WHEN PICKED UP
  The two threads move together. Hash at the call site in server.ts, then delete the scrub exemption
  in the same change. Removing the exemption alone just redacts every user into one bucket and kills
  the per user view the raw value was chosen for.

HONEST QUESTION WORTH ASKING FIRST
  Is anyone actually using the Langfuse per user view? If not, the compliance cost is being paid for a
  feature nobody has opened, and omitting the field is free.

6. MODEL CHOICE RESTS ON A SYNTHETIC BENCHMARK                       [OPEN, needs item 3 first]
================================================================================
WHAT
  master = grok-4.5, worker = grok-4.20-0309-non-reasoning, chosen from a ping-tool latency probe
  (2.8s vs 1.4s round trip) and list pricing. No comparison of REPLY QUALITY on real turns has been
  run between grok-4.5 and the cheaper grok-4.20-0309-reasoning for the master role.

WHY IT MATTERS
  Master is 2.00/6.00 against 1.25/2.50 per 1M, on ~34k prompt tokens per turn. That is the single
  biggest per turn cost line and it is defended by a benchmark that answered "call the ping tool".

NOTE
  grok-4.20-0309-reasoning emitted a stray \confidence{80} token in the probe reply, which is a real
  risk for a user facing turn. That is an argument for keeping 4.5 on master, but it should be an
  argument made from a quality comparison, not from one probe.
