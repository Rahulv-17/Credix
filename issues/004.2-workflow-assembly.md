## What to build

Assemble the deterministic pipeline into a single Mastra workflow, with the **single-fetch** bureau
architecture: Hono fetches the profile once and passes it in; `preGuardrailStep` masks the passed-in
profile instead of re-fetching; specialist steps see only the **masked** profile. This closes
Sudhanshu review **#3** (the bureau-fetch block was duplicated across `server.ts`,
`pre-guardrail.ts`, `identity-check.ts`).

## Verified corrections (pre-flight — read before building)

Verified against the installed Mastra API (docs MCP `docs/workflows/control-flow.md`, `node_modules`
`.d.ts` for @mastra/core 1.45.0 / @mastra/memory 1.21.0) **and** the repo's actual step I/O schemas.
The architecture below is sound, but these gaps must be honoured or the workflow won't build/run.

**Wrong API shapes (do NOT copy from the parent §7 snippet):**
- `result.steps[].toolCalls`/`toolResults` are **`.payload`-wrapped** → read `tc.payload.toolName`,
  `tc.payload.args`, `tr.payload.result`, `tr.payload.toolCallId`. The parent's flat reads yield an
  empty `tool_calls_log`.
- 004.1 understand emits **`pre_guardrail`** and **`brief`** (NOT `guardrail_ok` / `entities`). Use
  those names in every branch condition and step input.
- `updateWorkingMemory` is `{ threadId, resourceId, workingMemory: <string> }` — not the parent's
  `{ resourceId, threadId, data:{...} }`. Moot here: **memory writeback is deferred** (see #6).
- `index.ts` agent registration makes an `index → agents → memory → index` cycle; keep the
  `libsqlStore` declaration **above** the agents-barrel import (see #7).

**Schema-continuity gaps (real step schemas — the literal `.then()` chain breaks at 2 seams):**
- All `.branch()` steps must share **one** input schema (= understand's output) and **one** output
  schema (`agentOutputSchema`). See #4/#5.
- `postGuardrailStep` is `{raw_response} → {response}`; it **drops `active_skill`**. And `composeStep`
  reads `response`/`channel`/`session_id`/`active_skill` **from its input (no `getInitData`)**. So a
  `.map()` seam is required immediately before compose to rebuild its input. See #3 (chain) + #8.

## Deliverables

### 1. `src/mastra/lib/bureau-fetch.ts` — shared `fetchBureau(user_id)`
Centralize URL shape (`${BUREAU_SIDECAR_URL ?? 'http://localhost:8000'}/internal/bureau/<id>`),
the `X-Internal-Token` header, and `encodeURIComponent(user_id)`. Return a discriminated result:
`{ ok: true, profile }` | `{ ok: false, notFound: true }` | `{ ok: false, status }`. Never logs the
URL/user_id. **Closes review #3.** Callers: Hono `server.ts` (004.3) and `preGuardrailStep`.

### 2. `src/mastra/steps/pre-guardrail.ts` — stop fetching
Read the pre-fetched profile from `getInitData()` (workflow input `bureau_profile`), run the
injection/scope filters, then `maskProfilePii(profile)`. Keep the deny-by-default masking from
Issue #1 untouched. No network call in this step anymore.

### 3. `src/mastra/workflows/credix-workflow.ts` — assemble (parent spec §7, reconciled + corrected)
- `inputSchema`: `{ user_id: string(10), message, session_id, channel, bureau_profile: record }`.
- Chain (note the **two** `.map()` seams — collapse-branch and build-compose-input):
  ```
  .then(decodeStep).then(preGuardrailStep).then(understandStep)
  .branch([...])           // 5 conditions below
  .map(collapseBranch)     // G2 → agentOutputSchema
  .then(postGuardrailStep) // {raw_response} → {response}
  .then(memoryWritebackStep) // no-op pass-through (#6)
  .map(buildComposeInput)  // G4 → compose inputSchema
  .then(composeStep).commit()
  ```
- `.branch()` conditions use **`pre_guardrail`** (the field understand actually emits):
  1. `({inputData}) => !inputData.pre_guardrail` → `guardrailRejectStep`
  2. `... pre_guardrail && intent === 'score_improvement'` → `scoreStep`
  3. `... pre_guardrail && intent === 'credit_card'` → `cardStep`
  4. `... pre_guardrail && intent === 'insurance'` → `insuranceStep`
  5. `... pre_guardrail` (fallback, incl. `bureau_query`/`general`) → `generalStep` (credix)
- **collapseBranch `.map()`**: `getStepResult(STEP_IDS.GUARDRAIL_REJECT) ?? getStepResult(STEP_IDS.SCORE_IMPROVEMENT)
  ?? getStepResult(STEP_IDS.CREDIT_CARD) ?? getStepResult(STEP_IDS.INSURANCE) ?? getStepResult(STEP_IDS.GENERAL)`
  → `agentOutputSchema` (exact `STEP_IDS.*` constants — a typo silently returns `undefined`).
- **buildComposeInput `.map()`** (see #8): rebuild compose's input — `response` from
  `getStepResult(STEP_IDS.POST_GUARDRAIL)`, `channel`/`session_id` from `getInitData()`, and
  `active_skill` recovered via `getStepResult(<each branch id>)?.active_skill` (postGuardrail dropped it).

### 4. `makeAgentStep(agent, id)` factory
- **`inputSchema` = understand's output schema** (all branch steps share it — see #5): reads
  `pre_guardrail`, `intent`, `brief`, `masked_profile`, etc. `outputSchema = agentOutputSchema`.
- Inject into the prompt: the **masked** profile summary (read `masked_profile` from the step chain;
  **lowercase** bureau keys — verify `score`/`credit_score` against `config/scrub_mapping.yaml`) **and
  the understand `brief.points`** from 004.1. `user_id`/`message`/`session_id` via `getInitData()`.
- `agent.generate(prompt, { maxSteps: 3, memory: { resource: user_id, thread: session_id } })`.
- Build `tool_calls_log` from **`result.steps[].toolCalls[].payload` / `toolResults[].payload`**
  (`payload.toolName`, `payload.args`, `payload.result`, matched on `payload.toolCallId`) — the
  `.payload` wrapper is mandatory or the log is empty.
- Guard: `raw_response = result.text.trim() || 'I was unable to generate a response. Please try again.'`
- Output `agentOutputSchema = { raw_response, tool_calls_log, active_skill }` (`active_skill = id`).

### 5. `guardrailRejectStep`
**Same `inputSchema` as the specialists** (understand's output schema — branch steps must all share one)
and **same `outputSchema`** (`agentOutputSchema`). Polite redirect by `guardrail_reason` (injection vs
out_of_scope). No LLM call. `active_skill = STEP_IDS.GUARDRAIL_REJECT`.

### 6. `src/mastra/steps/memory-writeback.ts` — DEFERRED (no-op pass-through)
Memory writeback is **Postgres-memory work, deferred past 004.2** (decision). Do **not** call
`updateWorkingMemory` here. Keep the step but make it a **pass-through**: `inputSchema` /
`outputSchema` both `{ response: z.string() }`, `execute` returns its input unchanged. This keeps the
chain structurally complete and re-enabling later is a one-step change. (Specialist agents still carry
`credixMemory`, so working memory can be revisited via the agents' built-in tool later.)
> Note for the future: the real call is `credixMemory.updateWorkingMemory({ threadId, resourceId,
> workingMemory: <string> })` — and schema-mode direct-write merge semantics must be verified first.

### 7. `src/mastra/index.ts` — register
Add `agents: { scoreImprovementAgent, creditCardAgent, insuranceAgent, credixAgent }` and
`workflows: { credixWorkflow }` (camelCase keys) to the existing `new Mastra({ storage: libsqlStore })`.
**Ordering matters:** declare/`export const libsqlStore` **before** importing the agents barrel —
the `index → agents → memory → index` cycle resolves only if `libsqlStore` exists when `memory/index.ts`
reads it.

### 8. Compose feed (`buildComposeInput` `.map()` seam — production-grade data contract)
`composeStep` reads `{ response, channel, session_id, active_skill? }` **from its input** (it does not
use `getInitData`), but the chain drops `active_skill` at postGuardrail and never re-supplies channel/
session_id. So the `.map()` before `composeStep` (see #3) is **required**, not optional. Chosen over
editing `compose.ts` to keep the Issue-002-tested step pure and the data contract explicit at the
workflow level.

## Tests (`bun:test`)
Workflow-level test with agents mocked via `mock.module('@mastra/core/agent', ...)` — the workflow/
agents must be imported so the mock applies (agents are module-level singletons; mind the alphabetical
file-ordering trick from 004.1's `agents.test.ts`). Assert: each intent routes to the right step;
`!pre_guardrail` → guardrail-reject path with **no specialist call**; the collapse `.map()` returns the
fired branch's `agentOutputSchema`; `tool_calls_log` is non-empty (from `.payload.*`) when a mocked
specialist reports tool calls; the final `composed`/`active_skill`/`session_id` survive the
buildComposeInput seam. `bunx tsc --noEmit` is itself the schema-continuity gate (it fails on any seam
mismatch). Then run the `mastra-smoke-test` skill against `mastra dev`.
