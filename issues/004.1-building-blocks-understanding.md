## What to build

The standalone pieces 004.2 will wire together: the Rahul persona, the 4 specialist agents as real
`Agent` instances, the `checkCardEligibility` tool, the `credixMemory` singleton, and a redesigned
`understandStep` that uses a **thinking model + structured output** to classify intent *and* emit a
decomposed "brief" for the specialists.

## Deliverables

### 1. `src/mastra/agents/persona.ts`
`RAHUL_PERSONA` static string (parent spec §1): ≤120 words/response; money/scores/percentages as
digits only; never emit PAN/Aadhaar/full mobile; never fabricate data (only tool outputs); explain
jargon; trust tool results over assumptions.

### 2. Four agents — real `new Agent(...)`
`src/mastra/agents/{score-improvement,credit-card,insurance,credix}.ts`, each using `grokModel`
(from [lib/provider.ts](../src/mastra/lib/provider.ts)), `instructions: RAHUL_PERSONA` (+ a line for
insurance/credix), `memory: credixMemory`, and tools:
- score-improvement → `getBureauProfile`, `getBureauDetail`
- credit-card → `getBureauProfile`, `getBureauDetail`, `checkCardEligibility`
- insurance → none (Phase-3 stub, no product promises)
- credix → `getBureauProfile` (general fallback; never returns empty string — guard lives in 004.2's `makeAgentStep`)

Wiring `grokModel` here **closes Sudhanshu review #4** — the exports stop being dead and the
`.env.example` "passed to grokProvider()" comment becomes accurate.

### 3. `src/mastra/agents/index.ts`
Barrel: `export { scoreImprovementAgent, creditCardAgent, insuranceAgent, credixAgent }`.

### 4. `src/mastra/tools/eligibility.ts` — implement `checkCardEligibility`
`createTool` (mirror [tools/bureau.ts](../src/mastra/tools/bureau.ts) shape).
Input `{ cibil_score: number, monthly_income: number }`. Decision tree:
`score >= 750 && income >= 25000 → premium`; `score >= 650 → standard`; else `secured`.
Output `{ tier, reason }`. Pure function — no I/O.

### 5. `src/mastra/memory/index.ts` — `credixMemory` singleton
`new Memory({ storage: libsqlStore (import from ../index), options: { lastMessages: 20,
workingMemory: { enabled: true, scope: 'resource', schema } } })`.
Zod working-memory schema: `goals: string[]`, `hard_constraints: string[]`, `prose_summary: string`.
Schema (not template) → merge semantics. **One** `Memory` instance imported everywhere.
> Verify `Memory` + `updateWorkingMemory` API and `scope: 'resource'` against the installed
> `@mastra/memory` (1.21.0) reference before coding.

### 6. Redesign `src/mastra/steps/understand.ts` — thinking model + structured brief
Replace the raw `fetch` with Mastra structured output (`docs/agents/structured-output`):
`agent.generate(prompt, { structuredOutput: { schema, providerOptions: { openai: { reasoningEffort } } } })`
returns `response.object`. Grok runs via the OpenAI-compatible provider, so `reasoningEffort` applies.

Output schema (additive to current pass-through):
```
{
  pre_guardrail: boolean,
  guardrail_reason?: string,
  decoded_text: string,
  masked_profile?: Record<string, unknown>,
  intent: z.enum(INTENT_VALUES),
  brief: { summary: string, points: string[] },   // 2–5 points decomposing the request
  understand_error?: string,
}
```
Keep: the `pre_guardrail: false` short-circuit, and graceful degradation (non-2xx / network throw →
`intent: 'general'` + `understand_error: 'llm_<status>' | 'llm_unreachable'`, plus a `console.warn`).
Missing `GROK_API_KEY` still fails fast (config error).
> Confirm the chosen xAI model id supports reasoning effort (vs `grok-3`); make it env-tunable
> (e.g. `UNDERSTAND_MODEL` / `UNDERSTAND_REASONING`).
